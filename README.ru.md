# 2pack

[English](README.md) · **Русский**

Крошечный бинарный кодек со схемой для Node и браузеров. Пакет описывается один раз на TypeScript: тип выводится сам, байтов мало, а при разборе враждебных данных можно получить только один вид ошибки. Без зависимостей, без кодогенерации, буферами владеете вы.

> Версия 2 — переписанная с нуля и **несовместима с 1.x**: порядок полей, префиксы размеров и весь API изменились.

## Стек

TypeScript 6, только ESM, ноль зависимостей в рантайме, Node 18+ и любой современный браузер. Тесты на vitest.

## Быстрый старт

```ts
import { array, define, enumOf, i16, quant, str, u8, varuint, type Infer } from '@1337exp/2pack';

const Packet = define({
    kind: enumOf(['join', 'move', 'chat']),
    name: str(16), // не больше 16 байт UTF-8; длиннее — ошибка, без обрезки
    hp: i16,
    pos: define({ x: quant(-500, 500, 16), y: quant(-500, 500, 16) }), // по 2 байта, ошибка меньше 0,008
    items: array(define({ id: varuint, count: u8 }), 8),
});

type Packet = Infer<typeof Packet>; // { kind: 'join' | 'move' | 'chat'; name: string; hp: number; ... }

const bytes = Packet.pack({ kind: 'move', name: 'D', hp: -13, pos: { x: 12.5, y: -3 }, items: [{ id: 7, count: 2 }] });
const value = Packet.unpack(bytes); // с типом и проверкой, либо PackError
```

Несколько пакетов в одном буфере (заголовок, потом данные), без аллокаций:

```ts
const Header = define({ type: u8, version: u8 });
const Hello = define({ name: str(16), hp: i16 });
const buf = new Uint8Array(Header.max + Hello.max);

let n = Header.packInto(buf, { type: 3, version: 1 });
n += Hello.packInto(buf, { name: 'D', hp: 100 }, n);

const [header, at] = Header.unpackAt(buf, 0, n);
const payload = Hello.unpack(buf, at, n);
```

> **Прежде чем отправлять:** `packShared` быстрее всех, но следующий вызов перезаписывает его байты, а `socket.write()` при backpressure может удерживать их. См. [Буфер ваш](#буфер-ваш).

## Типы

| | |
|---|---|
| `bool` `u8` `i8` `u16` `i16` `u32` `i32` `f32` `f64` | фиксированный размер, little-endian |
| `u64` `i64` | 8 байт, `bigint` |
| `varuint` `varint` | от 1 до 5 байт, малые числа занимают один байт |
| `str(maxBytes)` `bytes(maxBytes)` | с префиксом длины, максимум обязателен |
| `array(item, maxCount)` `optional(item)` `enumOf([...])` | |
| `quant(min, max, bits)` | число из известного диапазона в 8, 16 или 32 битах |
| `define({...})` | запись, поля в порядке объявления, имена не передаются |
| `added(item, default)` | поле, добавленное в новой версии, последним в записи, см. [Как менять пакет](#как-менять-пакет) |

У каждого типа переменного размера объявлен максимум, поэтому у любого кодека конечные `min` и `max`: `new Uint8Array(codec.max)` всегда вмещает значение.

`str(n)` считает **байты** UTF-8, а не символы: `str(16)` вмещает 16 латинских букв, но только 8 русских. Строка, которая не влезла, даёт `PackError`, обрезки нет: тихая обрезка прячет ошибки (два длинных имени превращаются в одно). Ставьте потолок с запасом (не меньше 3 × лимит в `.length`) и проверяйте настоящий лимит там, где значение входит в приложение, например `name.length <= 32` при `str(255)`. По проводу идёт только реальная длина, поэтому высокий потолок байт не стоит.

Формат на уровне байтов описан в [docs/spec.md](https://github.com/1337exp/2pack/blob/main/docs/spec.md), эталонные байты в `tests/vectors.ts`.

## Как менять пакет

Пакеты строгие, и **строгий режим по умолчанию**: на проводе нет ни имён, ни тегов, читателю нужна схема, которой записан пакет, а любой байт после последнего поля — ошибка. Гибкость включается явно, для каждого сообщения, через `{ extensible: true }`. Поддерживается один вид изменений, и он ничего не стоит ни в байтах, ни в скорости: **дописывание полей в конец**.

```ts
// версия 1: сразу объявлена расширяемой, поэтому уже игнорирует поля, которые допишет следующая версия
const Player = define({ id: u32, name: str(16) }, { extensible: true });

// версия 2: новое поле последним, в обёртке added(); старый пакет читается со значением по умолчанию
const Player = define({ id: u32, name: str(16), shield: added(u16, 0) }, { extensible: true });
```

Работают оба направления: новый сервер со старым клиентом и старый сервер с новым клиентом. Новый читатель подставляет то, чего нет в старом пакете, старый читатель пропускает то, что дописал новый. Правила и то, чего это не умеет (удалять и переставлять поля, вкладывать), описаны в [docs/spec.md](https://github.com/1337exp/2pack/blob/main/docs/spec.md#evolution). Две вещи, которые надо знать: нужна граница пакета от транспорта (у сообщения WebSocket она есть), и расширяемая запись больше не считает лишние байты ошибкой (это цена включения).

## Буфер ваш

Три способа упаковки и страница, которая объясняет почему:

| | аллокации | байты |
|---|---|---|
| `pack(value)` | одна на пакет | ваши навсегда (по умолчанию, всегда безопасно) |
| `packInto(buf, value, offset?)` | нет | в **вашем** буфере |
| `packShared(value)` | нет | окно, следующий вызов его перезапишет |

Отдать окно от `packShared` в `socket.write()` — настоящая ошибка при backpressure: [Чьи это байты](https://github.com/1337exp/2pack/blob/main/docs/buffer-ownership.ru.md) показывает, как она случается, и объясняет. `npm run backpressure` воспроизводит её у вас на машине.

## Безопасно по построению

- Ничего не заворачивается и не обрезается: `300` в `u8`, `1.5` в `u16`, `NaN` в `i32` и строка длиннее лимита — ошибки с указанием места (`players[3].hp`).
- Разбор никогда не читает за пределами `[offset, end)` и сверяет каждую длину и с объявленным максимумом, и с оставшимися байтами. Миллиард элементов в десятибайтовом пакете отклоняется до всякого выделения памяти.
- Враждебные и битые байты дают `PackError` и ничего другого: проверено тестами с обрезанием каждого пакета на каждую длину и 40 000 случайных порч.
- Результаты — обычные объекты, которые владеют своими данными. `packInto` пишет только байты пакета.
- Те же проверки идут в настоящем браузере: `npm run browser` поднимает страницу, которая прогоняет на библиотеке эталонные векторы, фаззинг и случаи с изменяемыми буферами, а заголовок вкладки становится PASS или FAIL (проверено в Chromium; без зависимостей).

## Насколько ей можно доверять

Сериализатор стоит на границе с сетью, поэтому и тестировать его надо соответственно. Что прошла эта библиотека:

- **338 теста**, а формат на уровне байтов закреплён **53 эталонными векторами** из спецификации, посчитанными вручную: каждый проверен на упаковку, распаковку, запись в буфер точного размера и на то, что вокруг ничего не тронуто.
- **Воспроизводимый фаззинг** с зерном. Тысячи случайных пакетов проходят круг упаковки и распаковки; каждый пакет обрезается на каждую длину; в декодеры подаётся 40 000 случайных порч одного байта и 20 000 случайных буферов. Проверяемое правило: разбор враждебных байтов бросает `PackError` и ничего другого и не выделяет память под длину, которую вход не может подтвердить.
- **Проверка мутациями** (`npm run mutate`): код ломается 35 намеренными способами по одному (убрать проверку границ, перевернуть порядок байт, заворачивать вместо отказа и т. д.), и тесты обязаны заметить каждый. Замечают. С первого раза пропустили 2 из 19, это выявило два слабых теста, теперь исправлены.
- **Независимое состязательное ревью** другой модели (Grok): она прочитала спецификацию и написала собственные дифференциальные фаззеры против библиотеки. Нашла 6 ошибок, одна серьёзная (`packInto` писал байты после конца пакета), наши тесты её пропустили. Все исправлены, на каждую есть регрессионный тест (`tests/regressions.test.ts`).
- **Настоящий браузер**: `npm run browser` прогоняет 95 проверок на странице (Chromium 152).

Чего у неё **не было**: аудита безопасности людьми, боевого трафика, Firefox и Safari, big-endian машины. Версия 2 совсем новая, поэтому фиксируйте точную версию, пока она не отлежится.

## Скорость и размер

Одна машина (Node 22, Windows), мелкие объекты, медиана из 5 прогонов. Воспроизводится `npm run bench`. Сравнение по безопасному `pack`, который копирует.

| | размер | кодирование | разбор |
|---|---|---|---|
| **2pack**, запись 24 байта | **24 Б** | **108 нс** | **144 нс** |
| msgpackr | 57 Б | 217 нс | 195 нс |
| cbor-x | 58 Б | 205 нс | 334 нс |
| JSON (в байтах) | 70 Б | 442 нс | 763 нс |
| **2pack**, снимок из 20 юнитов | **144 Б** | **1246 нс** | **1265 нс** |
| msgpackr | 608 Б | 2164 нс | 3607 нс |
| cbor-x | 634 Б | 2554 нс | 3740 нс |
| JSON (в байтах) | 792 Б | 3849 нс | 4767 нс |

Выигрыш в размере структурный: когда схема есть у обеих сторон, имена и теги типов не передаются. Если схемой поделиться нельзя, берите msgpackr или cbor-x: они хороши.

## Пока нет

- **Удаления и перестановки полей.** Поддерживается только дописывание; остальное идёт через версию в небольшом кодеке-заголовке (см. спецификацию).
- **Второй реализации.** Формат описан по байтам, чтобы на другом языке можно было реализовать, но существует только TypeScript.
- **Сборки CommonJS.** Только ESM; Node 22 умеет `require()` для него.
